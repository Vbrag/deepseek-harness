# Agent Note: 协调已接受的持久化历史

Status: implemented

[English](2026-11-24-persistence-reconciliations.md) | 中文

## 问题

独立开发可能为同一持久化根创建相互竞争的转换。接受状态可能存在于定稿检查点之外，因此选择并改写某个分支可能破坏已接受的兼容性记录。单前驱历史无法同时描述两条转换及其合并后的后继。

## 决策

显式协调记录为每个受影响的根保存独立的前驱末端及完整的合并后 schema。验证器对来自每个前驱的转换进行分类，拒绝环、重复或存在依赖关系的前驱，以及没有唯一结果末端的分叉。作者提供兼容性决策和双语证据。协调记录作为历史保留；后续变化添加后继记录。

定稿检查点锁定每个前驱引用，并要求包含全部前驱。现有检查点摘要保持不变。[持久化历史决策](2026-09-11-persistence-type-history.zh.md)继续负责 schema 规范化、兼容性分类和检查点保留；本决策取代其中对已协调分叉使用单一前驱的要求。

## 考虑过的替代方案

**将一个分支改写为线性序列。** 其机器记录和快照可能已经被接受，改变前驱会错误描述已记录的转换。

**选择一个分支或保留竞争末端。** 选择一个会丢失兼容性历史；竞争末端无法标识当前源码应匹配的 schema。

## 影响

作者逐一评审前驱到合并后 schema 的转换，并说明两个方向的读取器行为。分类和已记录决策不能证明运行时兼容性，因此仍需测试和独立评审。[实操手册](../../../../docs/cookbook/reviewing-persistence-type-changes.zh.md)负责编写流程。此机制改变贡献者记录，不改变 Session wire 格式。
