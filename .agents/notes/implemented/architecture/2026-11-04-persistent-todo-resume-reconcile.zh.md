# Agent Note: 持久化的待办列表与恢复对账

状态: 已实现

[English](2026-11-04-persistent-todo-resume-reconcile.md) | 中文

## 问题

`todos` 会话投影在每次 `turn/start` 时把有效计划清空为 `null`，导致任何恢复或重启后的下一轮，模型之前追踪的计划就丢失了，人类不得不重新推导它。待办列表与事件溯源日志持有相同的生命周期价值，但折叠把每一轮的开始当作重置，而不是把最新整份 `todo/write` 当作权威值。

## 决定

`dsh-tool-todo` 的 `todos` 投影现在把最新整份 `todo/write` 列表跨轮次、跨恢复的会话持续保存。折叠只在 `todo/write` 时变化；显式空写入（`todo_write(todos: [])`）或人工 `/todo clear` 是唯一的清空路径。投影 `stateVersion` 从 `2` 升到 `3`，使持久化的检查点在新语义下重新折叠。

`dsh-todo-reconcile-driver` 是一个独立的宿主包，在 `agent/created` 来源为 `resume` 或 `startup`、且投影列表非空、且有当前目标时，入队一条 `<todo_reconcile>` 提示，要求模型通过 `todo_write` 对账状态——而不是提示人类。它用 `ctx.sessionProjections.snapshot(session).values['todos']` 读取持久化列表，用 `ctx.goals.get(agent)` 读取目标；它不注册自己的 `todos` 单元（该键已归 tool-todo 包所有）。准入在每个会话生命周期内一次性完成，并使用与 `goal-round-driver` 相同的竞态栅栏：仅在 agent 完全 idle 时运行、等待后代、请求持久化检查点、并在出现竞争性人类输入时撤回。失败的对账会被记录并解除武装，绝不循环重试。

## 考虑的替代方案

- **保留每轮清空，并在恢复时让人类重新规划。** 已否决，因为它保留了本次改动要消除的原始故障。
- **让对账驱动拥有 `todos` 投影键。** 已否决，因为会话投影注册表拒绝同一键的重复注册；驱动改为读取 tool-todo 拥有的值。
- **在后续轮次重新武装对账。** 已否决，因为重复提示会与模型和人类争夺转向；每次恢复的生命周期准入一次即可。

## 后果

列表在被显式清空前会跨重启与恢复持续存在；模型负责决定何时清空。带有未完工作的恢复会话获得一次自助对账，而不是人类提示。客户端与两个 SDK 继续以不变的形状投影 `todo/write` 与 `todos`，但其持久化行为不再显示轮次开始时的清空。

聚焦的投影、工具与对账驱动测试固定了持久化折叠、显式清空、单次准入对账、负例与竞争输入场景，以及 HMR 卸除。升级指南记录了面向模型的变化：列表不再每轮自动清空。
